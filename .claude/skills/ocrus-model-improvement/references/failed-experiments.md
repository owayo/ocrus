# 試して効かなかった手法（要約）

一次資料は `todo.md`。ここはその要約で、**同じ失敗を繰り返さないための最低限**。
再挑戦するなら「前回の失敗理由のどこが変わったのか」を先に言葉にすること。

## ❌ Multi-width Ensemble（複数スケールで推論して信頼度で選ぶ）

スケール 1.0 / 1.5 / 2.0 / 3.0 で推論し、最も信頼度の高い結果を採用。

- **結果**: 変化なし、または悪化（76.1% → 56.5% の条件もあった）
- **理由**: CTC の softmax 信頼度は**入力幅が違うと比較にならない**。パディングの無い
  自然幅が常に最高信頼度を返し、非 blank だけで測ると今度は大きいスケールを不当に優先する
- **再挑戦の条件**: 幅に依存しない校正済みスコアを用意できるとき。
  素の信頼度で選ぶ設計は何度やっても同じ結果になる

## ❌ 素の CTC Beam Search（全クラス、beam 幅 10）

- **結果**: 76.1% → 24.2%、速度は 16 倍悪化（0.18s → 2.96s/char）
- **理由**: 18,385 クラスに対する beam search は計算量が爆発し、確率計算も greedy と
  食い違って誤った候補を選ぶ
- **再挑戦の条件**: Top-K 枝刈りが前提。全クラス探索は選択肢にならない

## ⚪ Top-K Pruned Beam Search（`ctc_beam_decode_topk`）

- **結果**: 単文字ベンチでは TLA 単独と**完全に同じ数値**。追加の改善なし
- **理由**: 1 文字の画像では探索する余地がほとんど無い
- **現状**: API は `crates/ocrus-recognizer/src/ctc_beam.rs` に残っている。
  行文脈での評価や reranking と組み合わせるまで保留

## ⚠️ Retry-on-Empty（空出力のときだけ大きいスケールで再試行）

- **結果**: 半角記号のみ +1.2pt。他は変化なし
- **理由**: 空出力の大半は「モデルが根本的に認識できない文字」で、スケールの問題ではない
- **現状**: 費用対効果が低い。他に手が無いときの最後の候補

## ❌ 混同ペア Post-Correction（小書きかな向けの画像特徴補正）

前景 bbox の比率で `あ→ぁ` 系を補正するしきい値ルール。

- **結果**: step2 は変化なし（ひらがな 76.9%、カタカナ 68.6% のまま）
- **理由**: しきい値ベースの単純な特徴では、フォント差の方が大きくて分離できない
- **再挑戦の条件**: 特徴量の設計をやり直すとき。しきい値の調整だけでは動かない

## ✅ TLA / Temporal Logit Aggregation（`ctc_tla_decode`）

全タイムステップの確率を文字クラスごとに集約して最大票を返す。

- **結果**: 半角記号 +6.2pt、全角記号 +4.5pt。かな系はほぼ変化なし
- **理由**: 空出力寄り（blank 支配）の失敗に効く。安定誤認識には効かない
- **現状**: `char_accuracy` の評価経路では採用済み。**本番パイプライン
  （`ocrus-engine`）には未導入** — これが現在の最優先課題

## 未試行で有望とされているもの
